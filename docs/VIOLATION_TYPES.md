## Пометки по уверенности и ограничениям

- **T9 — контекст, не нарушение.** Выдаётся только в `meta.context_events`; вердикт не меняет; используется T3.
- **T6, T8, T11, T12 — индикаторы.** T6 и T8 в справочнике снабжены `caveat`; T6 по позе имеет пониженную уверенность.
  T11/T12 в ответах API не появляются. Сервис не утверждает факт хищения.
- **T3:** `rule.note` честно говорит, что норма требует автоблокировку по таймауту 30 минут, а сервис видит лишь активный
  экран после ухода кассира. Вариант «в темноте» не различает, какое именно устройство светится.
- **T4, T5, T10, T13 опираются на Правила № 14**, которые описывают устройство помещения (закрывающийся вход, оконный
  проём), а не поведение людей; связь с наблюдаемым признаком непрямая (`RULES_SOURCES.md` §7).
- **Неизвестные типы.** Для ситуаций вне T1–T13 есть страховочная сетка (`pipeline/safety_net.py`): S1 «посетитель остаётся
  один после ухода кассира» (T4, всегда включён) и предметные пробы с VLM (телефон, напиток/еда, личная сумка; нужна
  локальная VLM, на 8 ГБ ОЗУ выключена). Событие из сетки помечено `source: "safety_net"` и «требует проверки человеком».
- Названия типов — наши; соответствие типам жюри не гарантировано. Точный таймкод и верный вердикт важнее названия.

## Политика вердикта

`violation`, если есть хотя бы одно событие T1–T8, T10, T13 (и, при наличии, T11/T12 и событие страховочной сетки) с
`confidence ≥ 0.5`; иначе `no_violation`. Третьего вердикта нет (ТЗ). Таймкод события = начало нарушающего действия.
