# Документация к сдаче — оглавление

Пакет по разделу 8 ТЗ (кейс ForteBank, Datathon 26). Код пайплайна и API — `service/` (см. `service/README.md`).
Все документы на русском, согласованы с `ПЛАН_ForteBank.md` (§4, §12) и `service/pipeline/rules.py` /
`rules_scene.py` на версию пайплайна `0.3.0` (офлайн-оценка на 42 видео: 11 из 22 нарушений найдено, 0 ложных из 20).

## service/deploy/

| Файл | Назначение |
|---|---|
| `Dockerfile.gpu` | Образ на `nvidia/cuda:12.6.3-cudnn-runtime-ubuntu24.04` (Python 3.12), `onnxruntime-gpu`, `ORT_PROVIDERS=CUDA…` (детектор на GPU), те же зависимости, что в `requirements.txt`; `--build-arg WITH_VLM=1` ставит torch (cu126) + `requirements-vlm.txt`; `DOWNLOAD_MODELS=1` кладёт веса YOLOX в образ |
| `docker-compose.gpu.yml` | Проброс GPU (`deploy.resources.reservations.devices`), volume `service/models → /app/models` (YOLOX + `models/vlm`), `env_file: ../.env` (API_KEY, VLM_ENABLED), порт `${PORT:-8000}`; запускать из `service/`: `docker compose -f deploy/docker-compose.gpu.yml up --build -d` |
| `cloudflared.md` | Публичный URL: Cloudflare quick tunnel (без аккаунта) и ngrok (резерв), что передать жюри, что обработка остаётся локальной, как не уронить туннель во время проверки |
| `run_tunnel.sh`, `run_tunnel.ps1` | Поднимают туннель (`cloudflare` / `ngrok`) к `localhost:PORT` (по умолчанию 8000), печатают публичный URL и готовые строки для письма жюри |
| `gen_api_key.py` | `secrets.token_urlsafe(32)` → записывает/обновляет `API_KEY` в `service/.env`, печатает ключ (`--show` — показать текущий) |
| `healthcheck.sh` | `GET /health`, 401 без/с неверным ключом, `POST /api/v1/analyze` с видео по ТЗ, ожидание `done`, проверка схемы (поля ТЗ, JPEG base64, 1–3 кадра, `rule`), печать вердикта и типов. Проверен на локальном сервере (Х-3 → `no_violation`, Х-11 → `violation` T3) |

CPU-вариант — `service/Dockerfile` и `service/docker-compose.yml` (веса YOLOX скачиваются на этапе сборки).

## Что ещё нужно заполнить людьми

(1) **Реальный публичный URL** UI и API — после финального запуска туннеля или GPU-сервера вписать в
`SUBMISSION.md` §1 и в письмо (адрес quick tunnel меняется при каждом перезапуске). (2) **Ключ** —
`python3 service/deploy/gen_api_key.py` на машине с сервисом, тот же ключ в письмо. (3) **Метрики после
финального прогона `scripts\run_all.bat` на Windows** (`results/summary.md`, `results/eval.json`): если
изменились относительно 11/22, FP 0, 7/11 по таймкоду — обновить `ARCHITECTURE.md` §1 (слой 3), `LIMITATIONS.md` §2,
`VIOLATION_TYPES.md` (колонка «статус в коде» и список найденных), `PITCH.md` слайды 4 и 8. (4) Результат прогона
**собственных видео** с другого угла (`OWN_VIDEOS.md`) — таблица «ожидали / получили» сюда и на слайд 6 питча.
(5) Если на GPU-машине включён VLM (`VLM_ENABLED=1`) — замерить время на событие и вписать в `ARCHITECTURE.md` §4;
если не включён — на питче называть VLM опцией, а не частью демо. (6) Сверить дословные формулировки пунктов
Правил № 231 и № 14 на adilet; пункт постановления № 48 о блокировке сеанса АРМ — по-прежнему «уточнить на adilet».
(7) Если до сдачи включат T2/T6/T13 (после классификатора дверцы / калибровки двери) — обновить таблицу
включённых/выключенных правил в `ARCHITECTURE.md`, `VIOLATION_TYPES.md`, `LIMITATIONS.md`.
