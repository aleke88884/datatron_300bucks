Правила № 14 — «с изменениями на 24.12.2024», Требования ИБ — постановление АРРФР № 53 от 03.04.2026 (действующее)

## 1. Принцип сопоставления

1. Сервис фиксирует только **визуально наблюдаемый признак** (кассир вышел, дверца сейфа открыта, на столе
   лежит сумка). Описание события формулируется в терминах наблюдаемого («кассир вышел в 14.2 с; дверца сейфа
   в кадре открыта с 10.8 с по 20.9 с»), без вывода о виновности и о том, что невидимо на записи (замок двери,
   состояние пломбы, настройки автоблокировки). Каждое описание заканчивается пометкой «признак для проверки
   человеком» — результат сервиса является подсказкой для оператора (ТЗ, раздел 7).
2. Каждому типу нарушения T1–T13 сопоставлен **основной пункт** (поле `rule` ответа API: `document`, `clause`,
   `url`, `quote` — дословная выдержка, `note` — оговорка) и, при необходимости, **дополнительные пункты**
   (`secondary` в справочнике, показываются в UI и `/api/v1/rules`).
3. Если пункт лишь косвенно соответствует наблюдаемому признаку (T3, T8, T12), это **честно пишется в
   `rule.note`**, а не подбирается «похожий» пункт.
4. Пункты о хранилище (кладовая, сейфовая комната: R231 п. 74–76) не используются как основные для сейфа
   на рабочем месте кассира — для него есть прямая норма R231 п. 20 абз. 2 (запираемые на ключ устройства,
   прямо названы сейф и ящики стола).

### 2.3. Требования к обеспечению информационной безопасности (T3) — ответ на FAQ 32

Для T3 («экран АРМ остаётся активным после ухода кассира») в открытых актах РК найден точный пункт:
**п. 71 пп. 9) Требований к обеспечению информационной безопасности банков, филиалов банков-нерезидентов РК
и организаций, осуществляющих отдельные виды банковских операций** (параграф 2 «Требования к процессу управления
паролями и блокировками учетных записей пользователей в информационных системах» главы 9).

- **Действующий акт:** постановление Правления Агентства РК по регулированию и развитию финансового рынка
  от 03.04.2026 № 53, зарегистрировано в Минюсте 06.04.2026 № 38336, статус «Действующий».
  adilet: https://adilet.zan.kz/rus/docs/V2600038336 (зеркало: https://zakon.uchet.kz/rus/docs/V2600038336).
- **Историческая редакция:** постановление Правления НБРК от 27.03.2018 № 48, рег. № 16772
  (https://adilet.zan.kz/rus/docs/V1800016772) — утратило силу постановлением АРРФР от 03.04.2026 № 53
  («вводится в действие по истечении десяти календарных дней после дня первого официального опубликования»).
  Норма п. 71 пп. 9) в обеих редакциях текстуально совпадает. Поскольку открытый набор данных мог готовиться по
  постановлению № 48, оно указывается во вторичных ссылках и в `rule.note`.

**Ограничение, которое честно пишется в `rule.note` и в описании события.** Норма устанавливает автоматическую
блокировку (или завершение сеанса) по таймауту 30 минут неактивности, а не блокировку в момент ухода кассира.
Активный экран после ухода сам по себе п. 71 пп. 9) не нарушает; сервис фиксирует наблюдаемый признак («экран
остаётся активным N с после ухода кассира») как подсказку для проверки человеком. Фраза «рабочее место при уходе
не заблокировано» из прежних описаний удалена как вывод, а не наблюдение. Дополнительный пункт —
R231 п. 16 (кассовые операции в рамках системы управления рисками и внутреннего контроля).

Не используем: утратившие силу правила 2012 г. (https://zakon.uchet.kz/rus/docs/V1200007995), акты других
юрисдикций, внутренние документы банков.

## 6. Где это в коде и как проверяется

- `service/pipeline/rules.py` — `DOCUMENTS` (полные названия, рег. номера, ссылки, редакции, примечания), `CLAUSES`
  (пересказ пунктов для UI), `QUOTES` (дословные выдержки), `RULES` (тип → название, признак, основной и
  дополнительные пункты с `quote`/`note`, примеры видео).
- `GET /api/v1/rules` отдаёт этот справочник; UI показывает документ, пункт, ссылку и оговорку рядом с каждым событием;
  поле `rule.quote` в ответе API содержит дословную выдержку.
- `tests/test_rules.py`: все пункты из `RULES` есть в `CLAUSES`; для каждого пункта есть цитата; цитаты дословно
  присутствуют в этом файле; T3 привязан к п. 71 пп. 9); в описаниях нет запрещённых выводов; ссылки только на adilet.

## 7. Пометки честности

- **Непрямая связь для T4, T5, T10, T13.** Правила № 14 (п. 8, п. 16 пп. 1), 3), 4), п. 21) описывают, как устроен кассовый узел
  (один закрывающийся служебный вход, дверь на замок, оконный проём, транспортирующие устройства), и не содержат запрета на
  присутствие постороннего, положение клиента или момент закрытия двери. Мы сопоставляем наблюдаемое событие (человек вошёл
  и остаётся; дверь открыта ≥ 6 с) с ближайшей открытой нормой по устройству помещения; видео не показывает, запирается ли
  дверь. Поэтому вывод о нарушении остаётся человеку, а ссылка — подсказка, где искать норму.
- **T3.** Тип сохранён, потому что размеченное Х-28 — нарушение, но `rule.note` прямо говорит, что активный экран после ухода
  норму п. 71 пп. 9) сам по себе не нарушает; сервис не видит ни таймаута, ни состояния сеанса.
- **Правила № 14, п. 16.** Цитируется переходная редакция на период приостановления до 01.01.2027; утверждение «текст
  подпунктов совпадает с первоначальной редакцией» из зеркала проверить нельзя. После 01.01.2027 смысл п. 16 может измениться.

  нужно перечитать на adilet в браузере (в TODO).

  «вероятно, пересчёт»); они правятся отдельно, ограничение на формулировки в `rules_scene.py` проверяется тестом, но
  охватывает не все модули.
