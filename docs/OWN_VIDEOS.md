# Протокол съёмки собственных видео (проверка устойчивости к другому ракурсу)

Зачем: финальное тестовое видео снято под другим углом (ТЗ, критерий 5 «устойчивость», 10 баллов). FAQ кейса
приветствует собственные данные. Снимаем 12 коротких роликов телефоном **с другого угла**, прогоняем пайплайн,
результат — в `LIMITATIONS.md` §3 и на слайде 7 питча.

## Общие требования к съёмке

- **Ракурс:** не как в датасете (там камера сверху из угла, портрет 464×848). Берём камеру **с другого угла
  комнаты, ниже (≈1,6–1,8 м), под 30–45° к столу**. Один ракурс для всех 12 роликов, чтобы результат был
  сопоставим. Опционально — 2–3 ролика повторить с третьего ракурса.
- **Ориентация:** портрет (как в датасете) — основной; один-два ролика можно в ландшафте для проверки.
- **Формат:** `.mov` с телефона (iPhone — по умолчанию; Android — `.mp4`, тоже допустимо), 30 к/с, 1080p
  или ниже. Без звука не обязательно — звук сервис не использует.
- **Длительность:** 15–40 с на ролик; один «длинный» (≈2 мин) для проверки времени обработки.
- **Что обязательно в кадре:** стол целиком, «сейф» (тумба, шкафчик или коробка с открывающейся дверцей),
  ноутбук экраном к камере (чтобы было видно, активен ли экран), дверь/вход в комнату, стул «клиента»
  напротив стола. Камера неподвижна (штатив/подставка).
- **Реквизит:** пачка бумаги/«купюры» (любые бумажки размера купюры, лучше несколько пачек), зелёная или
  любая заметная сумка — «инкассаторская», личная сумка/рюкзак, стакан/банка, телефон, куртка.
- **Люди:** 2–3 человека: «кассир» (сидит за столом с начала ролика), «клиент» (садится на стул напротив),
  «посторонний/инкассатор» (входит позже). Лица не важны — роли определяются по положению.
- **Освещение:** обычное; один ролик с выключением света (см. T3).
- **Начало ролика:** первые 3–5 с кассир сидит за столом один, ничего не происходит — так пайплайн
  определяет роль кассира и строит медианный кадр сцены.

## Именование и размещение

- Имя файла: `own-<NN>-<тип или clean-...>.mov`, латиницей (в датасете часть имён кириллицей «Х-», это
  источник путаницы — у себя используем только латиницу).
- Папка: `open/own/` — она внутри `open/`, который целиком в `.gitignore` (условие кейса — датасет и
  производные не публикуются; свои видео тоже не коммитим, они с людьми).
- Рядом — `open/own/own_labels.csv` с колонками `file,type_code,expected_verdict,expected_timecode_sec,notes`,
  заполняется при съёмке (таймкод — по секундомеру или позже по плееру).

```
open/
├── videos/            датасет кейса
├── open_labels.xlsx
└── own/               свои видео (не в git)
    ├── own_labels.csv
    ├── own-01-T1.mov
    └── ...
```

## Как прогнать

```bash
cd service
# сервис запущен (deploy/start_public.sh или uvicorn); все свои ролики по одному, вердикт/тип/таймкод/время — в JSON
.venv/bin/python scripts/batch_check.py --sequential --base http://127.0.0.1:8000 \
    --out results/own_videos.json ../open/own/*.mov
# один файл через API с проверкой схемы ответа
deploy/healthcheck.sh ../open/own/own-01-T1.mov http://localhost:8000
```

`results/own_videos.json` содержит только вердикты, типы, таймкоды и время (без кадров) — его можно коммитить.

Для каждого ролика фиксируем в `own_labels.csv` (колонка `notes`): вердикт пайплайна, тип, таймкод, разница с
ожидаемым. Итоговая таблица «ожидали / получили» — в `LIMITATIONS.md` §3 и на слайде 7 питча. Критерий успеха:
0 ложных на двух чистых, ≥ половины нарушений найдены с ошибкой таймкода ≤ 3 с.

## Что проверяем этим протоколом

- Зоны строятся от детекций (стол/дверь/сейф), а не от пикселей (ПЛАН §5.3).
- Роль кассира определяется по поведению в первые секунды.
- Пороги «внутри кассы» и «за линией стола» не завязаны на конкретную камеру.
- Состояние экрана при другом угле к ноутбуку.
- Время обработки на 2-минутном видео 1080p (больше пикселей, чем в датасете).
