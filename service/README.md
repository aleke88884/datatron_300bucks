# Сервис контроля кассовой дисциплины по видео (Datathon 26, кейс ForteBank)

Локальный веб-сервис + API: принимает `.mov`-запись кассы, выдаёт вердикт `violation` / `no_violation`,
список событий с таймкодом, кадрами-доказательствами (JPEG base64) и ссылкой на пункт нормативного акта РК.
Всё выполняется локально: без облачных AI-сервисов, без распознавания лиц, видео удаляется после анализа.

Структура:

```
service/
├── app/            FastAPI: эндпоинты, X-API-Key, очередь (один воркер-процесс, таймаут 240 с)
├── pipeline/       анализ видео: video.py (OpenCV/FFmpeg), detectors.py (правила T1–T13; реализованы T9 и T3), rules.py (нормативка)
├── static/         фронтенд — одна страница, без сборки
├── scripts/smoke.sh
├── Dockerfile, docker-compose.yml, requirements.txt, .env.example
```

## Запуск локально

Нужен Python 3.12. Системный ffmpeg не требуется (используется ffmpeg из `imageio-ffmpeg`/OpenCV).

```bash
cd service
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # и задайте API_KEY (python3 -c 'import secrets;print(secrets.token_hex(16))')
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Интерфейс: http://localhost:8000 · Swagger: http://localhost:8000/docs · здоровье: `GET /health`.

## Запуск в Docker (CPU)

```bash
cd service
cp .env.example .env            # задайте API_KEY
docker compose up --build -d
curl -s http://localhost:8000/health
```

После сборки образа интернет не нужен (веса моделей добавляются в образ на этапе сборки).

## API (раздел 10 ТЗ)

Все запросы к `/api/v1/*` требуют заголовок `X-API-Key`; без ключа или с неверным — `401`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/analyze` | multipart-поле `file` (.mov, до 300 МБ) → `{"job_id": "..."}` (HTTP 202) |
| GET | `/api/v1/jobs/{job_id}` | статус `processing` / `done` / `failed` и результат |
| GET | `/api/v1/rules` | справочник типов нарушений и нормативных пунктов |
| GET | `/health` | без ключа; состояние воркера и очереди |

Пример (из ТЗ):

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
     -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
```

```bash
curl -H "X-API-Key: <ключ>" http://localhost:8000/api/v1/jobs/3f2a9c1e
```

Ответ при завершении (поля ТЗ + расширения `type_code`, `confidence`, `rule`, `end_sec`, `meta`; пример — `Х-11.mov`):

## Прогон на другой машине (Windows): сбор признаков для настройки правил

Правила T1–T13 настраиваются по числовым признакам, собранным со всех 42 видео (люди и треки — YOLOX-m через
ONNX Runtime, состояния двери/сейфа/экрана/стола — по медианному кадру и кропам). Прогон тяжёлый (20–40 минут на
ноутбуке), поэтому вынесен в отдельный скрипт, который кладёт результаты в `service/results/` и пушит их в репозиторий.
Изображения и кадры при этом не сохраняются — только JSON с числами (условия кейса запрещают публиковать датасет).

Что нужно на машине: Python 3.11–3.13 с python.org (галочка «Add python.exe to PATH»), git с доступом к репозиторию,
датасет в `<репозиторий>\open\videos\*.mov` и `<репозиторий>\open\open_labels.xlsx` (папка `open/` не в git).

```bat
cd <репозиторий>\service
scripts\run_all.bat
```

Скрипт (`scripts/run_all.ps1`) сам создаёт `.venv`, ставит зависимости, скачивает веса (`scripts/get_models.py`,
97 МБ с GitHub-релиза YOLOX), запускает `scripts/collect_features.py` по всем видео (детекции + состояния), затем
`scripts/eval_rules.py` (таблица правил против разметки → `results/eval.txt`, `results/eval.json`), прогоняет `pytest`
без Docker (лог в `results/pytest.log`), при `WITH_VLM=1` ставит зависимости VLM и скачивает Qwen2.5-VL-7B, и в конце
делает `git add results`, `commit`, `pull --rebase`, `push origin main`.
Прогресс печатается по видео; при ошибке на одном видео остальные обрабатываются, ошибка попадает в `results/run.log`.

Что появится в `service/results/`:

| Файл | Содержимое |
|---|---|
| `perception/<видео>.json` | детекции людей (bbox, «внутри кассы», id трека) и объектов на 3 к/с |
| `states/<видео>.json` | якоря сцены (стол, сейф, ноутбук, полоса двери) и признаки на 2 к/с: дверь (яркость/текстура полосы), сейф (фронт, кромка слева, отличие от медианы), экран (яркость, оттенок), стол (доля дерева, изменившиеся пятна, зелёная сумка, детекции предметов), число людей внутри |
| `verdicts.json`, `summary.md` | результат текущего пайплайна по каждому видео против разметки, время обработки, ошибки |
| `env.json`, `run.log`, `pytest.log` | окружение, журнал прогона, тесты |

Повторный запуск дописывает журнал и перезаписывает JSON. Отдельные видео: `python scripts/collect_features.py --names Х-11 Х-12`.
Веса в git не хранятся (`models/*.onnx` в `.gitignore`).


## Состояние пайплайна (0.3.0) и оценка на датасете

Слой восприятия подключён к `analyze_video`: детекции людей/объектов (YOLOX-m, ONNX Runtime) → треки → якоря сцены
(стол, сейф, ноутбук, дверь) и признаки состояний (`pipeline/states.py`) → роли, зоны и таблица состояний на сетке
2 к/с (`pipeline/scene.py`) → правила (`pipeline/rules_scene.py`, `pipeline/detectors.py`). Если детектор недоступен
(нет весов), пайплайн не падает: работают только правила по яркости (T9-контекст, T3 в темноте), а в `meta.perception_error`
записывается причина.

Офлайн-оценка по 42 обучающим видео (`scripts/eval_rules.py`, признаки из `results/`, 17.10.2026):

| | Значение |
|---|---|
| Нарушений найдено | 11 из 22 (Х-11, Х-13, Х-15, Х-17, Х-18, Х-24, Х-28, Х-30, Х-33, Х-38, Х-46) |
| Ложных на чистых | 0 из 20 |
| Таймкод в пределах 3 с | 7 из 11 (медиана ошибки 2.1 с) |
| Время на видео (кеш признаков) | ~0.3 с; живой путь с детектором на CPU (M4): 17-секундное видео — 6 с |

Что работает: T1 (ценности на столе + уход кассира), T3 (экран активен + уход; экран светится в темноте), T4 (третий человек
внутри), T5 (посетитель в рабочей зоне), T7 (купюры открыто на столе при входе посетителя), T8 (напиток на столе),
T10 (инкассаторская сумка сразу после входа посетителя), T9 — контекст.
Выключены как ненадёжные (флаги `*_ENABLED` в `rules_scene.py`): T2 (признак открытой дверцы сейфа растёт и в чистых
роликах, когда кассир стоит у сейфа), T6 (предмет на столе не отличает деньги от документов клиента), T13 (чистое Х-31 тоже
начинается с пустой кассы), T8-сумки по YOLO (путает с мебелью). Не реализованы: T11, T12 (индикаторы «в карман» и
«без пересчёта на машинке» — нужна поза рук). Светлые/коричневые купюры (5000 тг) на светлом дереве стола по цвету не
отделяются — Х-26, Х-4 пропускаются.

Переменные окружения пайплайна: `FEATURES_CACHE=<папка results>` — брать детекции/состояния из кеша (офлайн-оценка и
тесты); `EVIDENCE_FRAMES=0` — не кодировать кадры (быстрая оценка); `ORT_PROVIDERS=CUDAExecutionProvider,CPUExecutionProvider`
— провайдер ONNX Runtime; `YOLOX_MODEL=yolox_m.onnx` — файл весов в `models/`.

```bash
cd service && .venv/bin/python scripts/eval_rules.py            # таблица по 42 видео, ~15 с
cd service && .venv/bin/python scripts/eval_rules.py --names Х-28 Х-29 --json results/eval.json
```

## VLM-слой: человеческие описания событий (необязательно, нужен GPU)

Правила T1–T13 дают шаблонное описание события («кассир вне зоны стола, на столе наличные»). Локальная
мультимодальная модель **Qwen2.5-VL-7B-Instruct** (Apache-2.0, работает полностью офлайн — облачные API по условиям
кейса не используются) по 1–3 кадрам события переписывает шаблон в 2–3 предложения «что видно на кадрах».
Модель **не** ставит вердикт, не меняет тип, таймкод и уверенность; юридические выводы и описания внешности людей
отбраковываются постобработкой (`pipeline/vlm.py`). Шаблон сохраняется в поле `description_template` нарушения.
Без модели сервис работает как раньше — описания остаются шаблонными.

Включение на Windows с NVIDIA GPU (из папки `service\`, в активированном `.venv`):

```bat
pip install torch --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements-vlm.txt
python scripts\get_vlm.py
```

`get_vlm.py` скачивает веса с Hugging Face в `models\vlm\` (~16 ГБ, докачивает после обрыва; `--check` — только
проверить). Затем в `service\.env`:

```
VLM_ENABLED=1
# GPU с 8–12 ГБ видеопамяти: 4-битная загрузка (bitsandbytes), ~6 ГБ вместо ~16
VLM_4BIT=1
```

и перезапустить сервис. В логе при первом анализе появится `vlm: модель ... загружена за N с (device=cuda)`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VLM_ENABLED` | 0 | включить слой |
| `VLM_MODEL_PATH` | `service/models/vlm` | папка с весами |
| `VLM_4BIT` | 0 | 4-битная загрузка (только CUDA, пакет bitsandbytes) |
| `VLM_TIMEOUT_SEC` | 20 | таймаут одной генерации; при превышении остаётся шаблон |
| `VLM_MAX_EVENTS` | 5 | не более N событий на видео |
| `VLM_BUDGET_SEC` | 60 | суммарный лимит времени VLM на видео |
| `VLM_MAX_SIDE` | 768 | кадр уменьшается до этой длинной стороны (меньше токенов — быстрее) |

Ожидаемое время (3 кадра 768 px, до 120 токенов ответа): RTX 3060/4060 (8–12 ГБ, 4 бит) — 4–8 с на событие,
RTX 3090/4090 (bf16) — 2–4 с, первая загрузка модели — 30–90 с (один раз на воркер). На CPU модель 7B
непригодно медленная (десятки секунд и более на событие) — слой включать не стоит, он и так не обязателен.
С лимитами по умолчанию VLM добавляет к анализу видео не более ~60 с, лимит ТЗ в 5 минут не нарушается.

Qwen2.5-VL-**3B** не используем: у него Qwen Research License (только некоммерческое использование);
`get_vlm.py` откажется его качать без явного флага.

### Страховочная сетка (FAQ 9) на CPU / Apple Silicon — llama.cpp + Qwen3-VL-2B

`pipeline/safety_net.py` добавляет событие, только если правила ничего не нашли. Нужны три подтверждения: детектор
видел предмет ≥ 3 раз, VLM ответила «да» на ≥ 2 кадрах и «нет» на опровержениях и в контрольный момент. Подробности —
в `docs/ARCHITECTURE.md`, слой 4 (б). Без модели работает только структурный признак S1 (посетитель остался в кассе
один). Модели torch не нужен.

```bash
brew install llama.cpp                  # Windows/Linux: llama-server из релиза ggml-org/llama.cpp → models/vlm_gguf/bin/
python scripts/get_vlm.py --gguf        # Qwen3-VL-2B-Instruct GGUF (Apache-2.0), ~1.5 ГБ в models/vlm_gguf/
# в .env:
VLM_ENABLED=1
VLM_BACKEND=llamacpp                    # воркер сам запустит llama-server на 127.0.0.1:8977 (или VLM_SERVER_URL)
# проверка ворот на этой машине (FP на чистых = 0, время ≤ бюджета):
VLM_ENABLED=1 VLM_BACKEND=llamacpp python scripts/eval_safetynet.py
```

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SAFETY_NET` | auto | `auto` — предметный слой включается, если VLM доступна и успевает; `1` — плюс ответы из кеша `results/safety_net/` при `FEATURES_CACHE`; `0` — сетка выключена |
| `SAFETY_NET_STRUCTURAL` | 1 | структурный признак S1 |
| `SAFETY_NET_ALWAYS` | 0 | `1` — запускать предметный слой, даже если правила уже нашли нарушение |
| `SAFETY_NET_BUDGET_SEC` | 45 | бюджет времени предметного слоя на видео |
| `VLM_PROBE_MAX_SEC` | 8 | если замер скорости показал больше этого, модель для сетки не используется |
| `VLM_SERVER_URL` / `VLM_GGUF_DIR` / `VLM_LLAMA_BIN` | 127.0.0.1:8977 / models/vlm_gguf / PATH | где сервер, веса и бинарник |

Офлайн-оценка без модели: `SAFETY_NET=1 python scripts/eval_rules.py --no-frames` берёт закешированные ответы
модели (только true/false по ключу вопроса, без кадров).

## Пайплайн и как добавлять правила

`pipeline/analyze_video(path, progress) -> {"verdict", "violations", "meta"}` — единственная точка входа для воркера.

1. `pipeline/video.py` — декодирование (OpenCV, бэкенд FFmpeg), ряд яркости, выборка кадра по времени, JPEG/base64.
2. `pipeline/context.py` — `VideoContext` (общие данные видео: яркость; слоты `detections`, `tracks`, `states`, `zones`
   для слоя восприятия) и `Event` (что возвращает правило).
   Слой восприятия (подключён к `analyze_video`; тот же код использует сборщик признаков): `pipeline/detect.py` —
   YOLOX (ONNX Runtime, CPU, Apache-2.0), `pipeline/perception.py` — детекции на 3 к/с, треки людей и признак
   «внутри кассы» (по низу рамки относительно порога двери и матовой полосы стекла, с гистерезисом),
   `pipeline/states.py` — якоря сцены по медианному кадру и признаки состояний (дверь, сейф, экран, столешница).
3. `pipeline/scene.py` — роли (кассир = самый долгий уверенный трек у стола; посетители; фантомы за стеклом), рабочая
   зона (сторона стола, где кассир), таблица состояний 2 к/с; `pipeline/rules_scene.py` — правила T1, T2, T4–T8, T10, T13
   на этой таблице (с флагами включения). `pipeline/detectors.py` — список `DETECTORS`, T9 и T3-в-темноте по яркости. Реализованы:
   - **T9** (освещение выключено: падение средней яркости кадра > 40 % относительно предыдущих 3 с, удержание > 1 с).
     T9 — **контекстное** событие (`CONTEXT_ONLY_TYPES` в `pipeline/__init__.py`): не даёт вердикт, попадает в
     `meta.context_events`. Детекторы выполняются в две фазы: сначала контекстные, их события кладутся в
     `ctx.context_events`, затем правила-нарушения, которые этот контекст читают.
   - **T3** (экран АРМ остаётся активным после выключения света). Работает только при контексте T9: на тёмном
     участке с частотой 10 Гц строится карта «доля кадров, в которых пиксель светится (серый > 150)»; связные
     области, стабильные ≥ 80 % кадров, фильтруются по площади (0,03–1 % кадра), заполненности bbox (≥ 0,4),
     яркости (≥ 170) и локальному контрасту (яркость области ≥ ×3 яркости кольца вокруг неё). Самосветящийся
     экран в тёмной комнате даёт контраст ×4,5 (Х-11); проёмы в освещённый коридор, флипчарт за стеклом — ≤ ×2,6,
     идущий человек в светлой одежде размазывается по карте. В Х-12 крышка ноутбука закрыта — кандидатов нет.
     Таймкод = момент выключения света, `end_sec` = конец тёмного участка; кадры: до выключения, самый тёмный
     кадр после выключения (экран светится в темноте), конец участка — все с рамкой вокруг экрана (`draw.box`,
     координаты передаются через `Event.extras["evidence_boxes"]`).
   Остальные — заглушки с докстрингами: признак, ожидаемые входы, примеры видео. Список `DETECTORS` задаёт, что включено.
4. `pipeline/rules.py` — справочник `type_code → название, признак, документ, пункт, url` строго по разделу 4
   ПЛАН_ForteBank.md (Правила № 231 и № 14 НБРК). Выдуманных пунктов нет; перед сдачей сверить формулировки на adilet.
5. `pipeline/draw.py` — баннер-подпись на кадре (кириллица через Pillow + системный TTF; в Docker — DejaVu) и рамки.

Чтобы добавить правило: заполнить тело `detect_tN`, вернуть `Event(type_code, timecode_sec, description,
confidence, evidence_times=[...], evidence_captions=[...])`. Таймкод = момент перехода состояния (ПЛАН 5.4), описание —
только наблюдаемое (ПЛАН 4.4). Событие попадает в ответ при `confidence >= MIN_CONFIDENCE` (0.5).
Тяжёлые модели загружать в `pipeline.warmup()` — он вызывается один раз в воркер-процессе.

## Переменные окружения (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | — (обязательна) | ключ для `X-API-Key` |
| `MAX_UPLOAD_MB` | 300 | лимит размера файла |
| `JOB_TIMEOUT_SEC` | 240 | таймаут обработки одного видео |
| `KEEP_UPLOADS` | false | хранить ли видео после анализа (по ТЗ — нет) |
| `ALLOWED_EXTENSIONS` | `.mov,.mp4` | допустимые расширения |
| `DATA_DIR` | `service/data` | временные файлы загрузок |

## Ограничения каркаса и известные ошибки

- Реализованы два детектора по яркости кадра: контекстный T9 (свет выключен; срабатывает и на Х-11 — нарушение,
  разметка 18 с, — и на чистом Х-12, где кассир штатно гасит свет при пустом столе) и T3 поверх него (в темноте
  остаётся светящийся экран ноутбука → Х-11 `violation`, Х-12 `no_violation`). T3 не различает, *какое* устройство
  светится: любая компактная самосветящаяся область, неподвижная весь тёмный участок (например, дисплей прибора,
  оставленный включённым), будет описана как активный экран АРМ. Уход кассира при включённом свете (X-28) T3 пока
  не видит — нужен CV-слой (`ctx.states['cashier_in_room']`, `ctx.states['screen_unlocked']`).
- Остальные правила T1, T2, T4–T8, T10–T13 — заглушки, возвращают пустой список (в Х-11 по кадрам ещё и сейф
  открыт — это T2, он ждёт классификатор дверцы сейфа).
- Описания шаблонные, если VLM не включена (`VLM_ENABLED=1`, см. раздел «VLM-слой»).
- Результаты заданий хранятся в памяти процесса API до перезапуска; история проверок по ТЗ не требуется.
- Один воркер: видео обрабатываются по очереди (это сознательно: предсказуемое время и память).
