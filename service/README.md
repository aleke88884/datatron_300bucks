# Сервис контроля кассовой дисциплины по видео (Datathon 26, кейс ForteBank)

Локальный веб-сервис + API: принимает `.mov`-запись кассы, выдаёт вердикт `violation` / `no_violation`,
список событий с таймкодом, кадрами-доказательствами (JPEG base64) и ссылкой на пункт нормативного акта РК.
Всё выполняется локально: без облачных AI-сервисов, без распознавания лиц, видео удаляется после анализа.

Структура:

```
service/
├── app/            FastAPI: эндпоинты, X-API-Key, очередь (один воркер-процесс, таймаут 240 с)
├── pipeline/       анализ видео: video.py (OpenCV/FFmpeg), detectors.py (правила T1–T13; реализованы T9 и T3), rules.py (нормативка)
├── static/         фронтенд — одна страница, без сборки
├── scripts/smoke.sh
├── Dockerfile, docker-compose.yml, requirements.txt, .env.example
```

## Запуск локально

Нужен Python 3.12. Системный ffmpeg не требуется (используется ffmpeg из `imageio-ffmpeg`/OpenCV).

```bash
cd service
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # и задайте API_KEY (python3 -c 'import secrets;print(secrets.token_hex(16))')
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Интерфейс: http://localhost:8000 · Swagger: http://localhost:8000/docs · здоровье: `GET /health`.

## Запуск в Docker (CPU)

```bash
cd service
cp .env.example .env            # задайте API_KEY
docker compose up --build -d
curl -s http://localhost:8000/health
```

После сборки образа интернет не нужен (веса моделей добавляются в образ на этапе сборки).

## API (раздел 10 ТЗ)

Все запросы к `/api/v1/*` требуют заголовок `X-API-Key`; без ключа или с неверным — `401`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/analyze` | multipart-поле `file` (.mov, до 300 МБ) → `{"job_id": "..."}` (HTTP 202) |
| GET | `/api/v1/jobs/{job_id}` | статус `processing` / `done` / `failed` и результат |
| GET | `/api/v1/rules` | справочник типов нарушений и нормативных пунктов |
| GET | `/health` | без ключа; состояние воркера и очереди |

Пример (из ТЗ):

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
     -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
```

```bash
curl -H "X-API-Key: <ключ>" http://localhost:8000/api/v1/jobs/3f2a9c1e
```

Ответ при завершении (поля ТЗ + расширения `type_code`, `confidence`, `rule`, `end_sec`, `meta`; пример — `Х-11.mov`):

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Незаблокированное рабочее место (АРМ) при уходе",
      "timecode_sec": 16.06,
      "description": "В 16.1 с освещение в кассе выключено (свет гасят, покидая рабочее место), при этом экран ноутбука (АРМ) остаётся активным: в темноте до конца записи (25.6 с) ...",
      "evidence_frames": [
        {"timestamp_sec": 15.06, "image_base64": "/9j/4AAQ..."},
        {"timestamp_sec": 16.06, "image_base64": "/9j/4AAQ..."},
        {"timestamp_sec": 25.3, "image_base64": "/9j/4AAQ..."}
      ],
      "type_code": "T3",
      "confidence": 0.95,
      "end_sec": 25.6,
      "rule": {
        "document": "Правила осуществления кассовых операций ... (постановление Правления НБРК от 29.11.2019 № 231)",
        "clause": "п. 14",
        "url": "https://adilet.zan.kz/rus/docs/V1900019680",
        "note": "Прямого пункта о блокировке сеанса в Правилах № 231 нет; п. 14 — общее требование исключать противоправные действия. ..."
      }
    }
  ],
  "meta": {
    "duration_sec": 25.6, "fps": 29.883, "processing_time_sec": 2.3, "pipeline_version": "0.2.0",
    "context_events": [
```

На кадрах-доказательствах T3 вокруг светящегося экрана нарисована рамка, сверху — подпись (код, название, время, пояснение).
`meta.context_events` — контекст сцены (не нарушения): T9 «освещение выключено» с интервалом.

Статусы: `processing` (с полем `progress: {stage, percent}`), `done`, `failed` (с полем `error`).
Если обработка не укладывается в `JOB_TIMEOUT_SEC` (240 с), воркер-процесс убивается, задание получает `failed`.

## Пайплайн и как добавлять правила

`pipeline/analyze_video(path, progress) -> {"verdict", "violations", "meta"}` — единственная точка входа для воркера.

1. `pipeline/video.py` — декодирование (OpenCV, бэкенд FFmpeg), ряд яркости, выборка кадра по времени, JPEG/base64.
2. `pipeline/context.py` — `VideoContext` (общие данные видео: яркость; слоты `detections`, `tracks`, `states`, `zones`
   для слоя восприятия) и `Event` (что возвращает правило).
3. `pipeline/detectors.py` — правила `detect_tN(ctx) -> list[Event]` по таксономии T1–T13. Реализованы:
   - **T9** (освещение выключено: падение средней яркости кадра > 40 % относительно предыдущих 3 с, удержание > 1 с).
     T9 — **контекстное** событие (`CONTEXT_ONLY_TYPES` в `pipeline/__init__.py`): не даёт вердикт, попадает в
     `meta.context_events`. Детекторы выполняются в две фазы: сначала контекстные, их события кладутся в
     `ctx.context_events`, затем правила-нарушения, которые этот контекст читают.
   - **T3** (экран АРМ остаётся активным после выключения света). Работает только при контексте T9: на тёмном
     участке с частотой 10 Гц строится карта «доля кадров, в которых пиксель светится (серый > 150)»; связные
     области, стабильные ≥ 80 % кадров, фильтруются по площади (0,03–1 % кадра), заполненности bbox (≥ 0,4),
     яркости (≥ 170) и локальному контрасту (яркость области ≥ ×3 яркости кольца вокруг неё). Самосветящийся
     экран в тёмной комнате даёт контраст ×4,5 (Х-11); проёмы в освещённый коридор, флипчарт за стеклом — ≤ ×2,6,
     идущий человек в светлой одежде размазывается по карте. В Х-12 крышка ноутбука закрыта — кандидатов нет.
     Таймкод = момент выключения света, `end_sec` = конец тёмного участка; кадры: до выключения, самый тёмный
     кадр после выключения (экран светится в темноте), конец участка — все с рамкой вокруг экрана (`draw.box`,
     координаты передаются через `Event.extras["evidence_boxes"]`).
   Остальные — заглушки с докстрингами: признак, ожидаемые входы, примеры видео. Список `DETECTORS` задаёт, что включено.
4. `pipeline/rules.py` — справочник `type_code → название, признак, документ, пункт, url` строго по разделу 4
   ПЛАН_ForteBank.md (Правила № 231 и № 14 НБРК). Выдуманных пунктов нет; перед сдачей сверить формулировки на adilet.
5. `pipeline/draw.py` — баннер-подпись на кадре (кириллица через Pillow + системный TTF; в Docker — DejaVu) и рамки.

Чтобы добавить правило: заполнить тело `detect_tN`, вернуть `Event(type_code, timecode_sec, description,
confidence, evidence_times=[...], evidence_captions=[...])`. Таймкод = момент перехода состояния (ПЛАН 5.4), описание —
только наблюдаемое (ПЛАН 4.4). Событие попадает в ответ при `confidence >= MIN_CONFIDENCE` (0.5).
Тяжёлые модели загружать в `pipeline.warmup()` — он вызывается один раз в воркер-процессе.

## Переменные окружения (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | — (обязательна) | ключ для `X-API-Key` |
| `MAX_UPLOAD_MB` | 300 | лимит размера файла |
| `JOB_TIMEOUT_SEC` | 240 | таймаут обработки одного видео |
| `KEEP_UPLOADS` | false | хранить ли видео после анализа (по ТЗ — нет) |
| `ALLOWED_EXTENSIONS` | `.mov,.mp4` | допустимые расширения |
| `DATA_DIR` | `service/data` | временные файлы загрузок |

## Ограничения каркаса и известные ошибки

- Реализованы два детектора по яркости кадра: контекстный T9 (свет выключен; срабатывает и на Х-11 — нарушение,
  разметка 18 с, — и на чистом Х-12, где кассир штатно гасит свет при пустом столе) и T3 поверх него (в темноте
  остаётся светящийся экран ноутбука → Х-11 `violation`, Х-12 `no_violation`). T3 не различает, *какое* устройство
  светится: любая компактная самосветящаяся область, неподвижная весь тёмный участок (например, дисплей прибора,
  оставленный включённым), будет описана как активный экран АРМ. Уход кассира при включённом свете (X-28) T3 пока
  не видит — нужен CV-слой (`ctx.states['cashier_in_room']`, `ctx.states['screen_unlocked']`).
- Остальные правила T1, T2, T4–T8, T10–T13 — заглушки, возвращают пустой список (в Х-11 по кадрам ещё и сейф
  открыт — это T2, он ждёт классификатор дверцы сейфа).
- Описания шаблонные; VLM-слой для описаний не подключён.
- Результаты заданий хранятся в памяти процесса API до перезапуска; история проверок по ТЗ не требуется.
- Один воркер: видео обрабатываются по очереди (это сознательно: предсказуемое время и память).
