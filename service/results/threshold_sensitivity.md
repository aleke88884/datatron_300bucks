# Устойчивость порогов к сдвигу ±20 % (ПЛАН §14, 18.10.2026)

Скрипт: `scripts/threshold_sensitivity.py`; сырые результаты: `threshold_sensitivity.json` (только вердикты, без кадров).

Метод: каждый из 38 порогов уровня правил и сцены (`rules_scene.py` — 20, `rules_door.py` — 5, `rules_hands.py` — 7,
`scene.py` — 6) по очереди сдвигался на −20 % и +20 % (целочисленные — с округлением), остальные оставались как есть.
На каждом из 76 вариантов прогонялись все 42 видео по кешу признаков (`results/`), матрица — против `open/open_labels.xlsx`.
Базовая линия: **TP 17 / FN 5 / FP 0 / TN 20**.

## Итог

- **Ложных срабатываний не появилось ни в одном из 76 вариантов** (FP = 0 на 20 чистых роликах везде).
- **72 варианта из 76 результат не меняют.**
- 4 варианта теряют по одному найденному нарушению (TP 17 → 16):

| Порог | Значение (было) | Теряется | Что это значит |
|---|---|---|---|
| `rules_scene.T7_BEFORE_SEC` | 3.6 с (3.0) | Х-38 | купюры лежали открыто 3.0–3.6 с до входа — у границы |
| `rules_scene.T7_MIN_AREA` | 240 (200) | Х-38 | площадь пачки в кадре между 200 и 240 пикс. |
| `rules_scene.T10_WINDOW_SEC` | 4.0 с (5.0) | Х-17 | сумка оказалась на столе через 4–5 с после входа |
| `rules_hands.STAND_RATIO` | 1.62 (1.35) | Х-34 | рамка клиента при вставании выросла в 1.35–1.62 раза; T6 по позе подтверждён одним роликом |

Вывод для питча: нулевой уровень ложных срабатываний не держится на «подогнанных» порогах — он устойчив к сдвигу любого
порога правил на ±20 %. Полнота чувствительнее: T7 (Х-38), T10 (Х-17) и T6 по позе (Х-34) сидят ближе к границе.

## Чего эта проверка не покрывает

- Пороги признаков, которые лежат в кеше (детектор купюр `cashdetect.py`, область двери `door.py`, предметы
  `personal_items.py`, состояния `states.py`): для них нужен живой прогон по видео.
- Сдвиг нескольких порогов одновременно и другой ракурс: это проверяют `results/robustness.md` (синтетика) и собственные
  ролики (`docs/OWN_VIDEOS.md`).
- Отложенной выборки по-прежнему нет: пороги подбирались на тех же 42 роликах.
